# Astralink 灵枢教务系统 V1 历史数据导入方案

## 目标

将朗睿教育历史业务数据导入 V1 正式环境，确保上线时可以直接承接真实教务流程。导入范围包括学生、课程、老师、课时余额、历史排课、历史上课记录和订单数据。

## 总体原则

1. 先导入主数据，再导入业务数据。
2. 所有导入必须先预览，确认后再写入正式表。
3. 每次导入生成唯一导入批次号 `import_batch_id`。
4. 导入错误按行展示，不因单行错误中断整批预览。
5. 正式写入后保留导入日志，支持按批次回滚。
6. 客户正式上线前至少完成一次全量试导入和一次增量试导入。

## 导入顺序

| 顺序 | 数据类型 | 依赖 | 说明 |
|------|----------|------|------|
| 1 | 老师 Excel | 无 | 生成老师档案和可选账号 |
| 2 | 课程 Excel | 无 | 生成课程产品 |
| 3 | 学生 Excel | 顾问账号 | 生成学员主档 |
| 4 | 班级/选课 Excel | 学生、课程、老师 | 如客户有班级历史数据则导入 |
| 5 | 课时余额 Excel | 学生、课程 | 生成期初余额和期初流水 |
| 6 | 历史排课 Excel | 学生/班级、课程、老师、教室 | 导入历史课程安排 |
| 7 | 历史上课记录 Excel | 历史排课或学生/班级 | 导入已完成课程反馈 |
| 8 | 订单数据 Excel | 学生、课程 | 导入历史购买与付款信息 |

## 课时余额导入

### 模板字段

| 字段 | 必填 | 示例 | 校验规则 |
|------|------|------|----------|
| 学员手机号 | 是 | 13800000001 | 必须匹配已导入学员 |
| 学员姓名 | 否 | 张子涵 | 用于人工核对 |
| 课程名称 | 否 | AP微积分BC | 可选，生成流水快照 |
| 当前余额 | 是 | 20 | 大于等于 0 |
| 累计购买 | 否 | 40 | 大于等于当前余额 |
| 累计消耗 | 否 | 20 | 大于等于 0 |
| 到期日期 | 否 | 2027-06-30 | 日期格式 |
| 备注 | 否 | 历史期初余额 | 长文本 |

### 写入目标

- `credit_accounts`
- `credit_transactions`，生成 `manual` 或 `purchase` 类型的期初流水

### 关键规则

- 同一学员只允许有一个当前账户余额。
- 导入余额必须与客户财务最终核对表一致。
- 每条余额导入都必须生成流水，避免只有余额没有来源。

## 导入预览

### 预览内容

| 内容 | 说明 |
|------|------|
| 总行数 | Excel 数据总行 |
| 可导入行数 | 校验通过的行 |
| 错误行数 | 校验失败的行 |
| 新增数量 | 系统中不存在，将创建 |
| 更新数量 | 匹配到已有数据，将更新 |
| 跳过数量 | 重复或无变化数据 |
| 关联缺失 | 如老师、课程、学员未匹配 |

### 预览动作

1. 上传 Excel。
2. 解析字段并做格式校验。
3. 做唯一性和关联校验。
4. 展示逐行结果。
5. 客户下载错误文件修正。
6. 预览通过后点击“确认导入”。

## 导入错误提示

| 错误类型 | 展示示例 | 处理建议 |
|----------|----------|----------|
| 必填缺失 | 第 12 行：手机号不能为空 | 补全字段后重新上传 |
| 格式错误 | 第 3 行：入学日期格式错误 | 使用 YYYY-MM-DD |
| 枚举错误 | 第 8 行：课程分类 physicsx 不存在 | 使用模板枚举 |
| 重复数据 | 第 15 行：手机号已存在 | 确认是更新还是跳过 |
| 关联不存在 | 第 22 行：老师王老师不存在 | 先导入老师或修正姓名 |
| 业务校验失败 | 第 9 行：消耗课时不能小于 0 | 修正数值 |

## 导入回滚

### 回滚粒度

| 粒度 | 说明 |
|------|------|
| 单批次回滚 | 回滚某一次确认导入产生的数据 |
| 单对象回滚 | 仅回滚某批次中的学生、课程等对象 |
| 全量试导入清空 | UAT 环境可清空所有导入数据 |

### 回滚规则

1. 所有导入写入必须带 `import_batch_id` 或写入导入日志表。
2. 回滚前生成影响范围预览。
3. 已被后续业务引用的数据默认禁止直接删除。
4. 可删除的数据执行物理删除；已引用数据执行归档或反向流水。
5. 课时余额和订单相关数据必须通过反向流水回滚，不直接改余额。

### 建议新增导入日志表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 导入批次 ID |
| organization_id | UUID | 机构 |
| import_type | 文本 | student/course/teacher/credit/schedule/lesson/order |
| file_name | 文本 | 上传文件名 |
| total_rows | 数字 | 总行数 |
| success_rows | 数字 | 成功行数 |
| failed_rows | 数字 | 失败行数 |
| status | 文本 | previewed/imported/rolled_back/failed |
| created_by | UUID | 操作人 |
| created_at | 时间 | 创建时间 |
| imported_at | 时间 | 正式导入时间 |
| rolled_back_at | 时间 | 回滚时间 |

## UAT 导入演练计划

| 阶段 | 数据量 | 目标 |
|------|--------|------|
| 模板确认 | 每类 5-10 行 | 确认字段、枚举和格式 |
| 小批量试导入 | 真实数据 50-100 行 | 验证关联和错误提示 |
| 全量试导入 | 客户完整历史数据 | 验证性能和余额一致性 |
| 增量试导入 | 新增最近一周数据 | 验证上线切换流程 |
| 正式导入 | 冻结后的最终数据 | 支撑正式上线 |

## 上线数据冻结建议

1. 上线前 2 天冻结课程、老师和班级主数据。
2. 上线前 1 天冻结订单和课时余额。
3. 上线当天导入最近新增排课和上课记录。
4. 导入完成后由财务核对课时余额总数、订单总金额和学生数量。
5. 验收通过后开放正式账号。
