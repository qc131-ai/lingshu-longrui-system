# Astralink 灵枢教务系统 V1 正式版上线计划

## 上线目标

V1 正式版目标是支撑朗睿教育真实教务运营的核心闭环：学员建档、课程班级、排课、上课反馈、消课扣费、课时流水、请假补课、家长报告和基础 AI 教务提醒。

## 开发范围

### V1 必须交付范围

| 模块 | 范围 |
|------|------|
| 登录与权限 | 五类角色、菜单权限、后端接口权限、数据范围控制 |
| 学员管理 | 新增、查看、编辑、归档、导入、导出 |
| 课程产品 | 课程创建、编辑、状态管理、导入、导出 |
| 班级管理 | 班级创建、学员加入、容量控制、班级状态 |
| 老师中心 | 老师档案、可用时间、关联账号、老师课表 |
| 排课日历 | 新建排课、取消排课、冲突检测、列表筛选 |
| 上课记录 | 记录生成、老师反馈、AI 摘要、反馈状态 |
| 消课与课时 | 确认消课、课时扣减、课时流水、余额核对 |
| 请假补课 | 申请、审批、安排补课、扣课时规则 |
| 家长报告 | 报告生成、预览、状态更新、模拟发送 |
| AI 教务助手 | 低课时查询、反馈待提交、作业逾期、报告摘要 |
| 文件上传 | 学员材料、作业附件、合同、报告文件 |
| 操作日志 | 覆盖关键写操作 |
| 数据导入 | 学生、课程、老师、余额、排课、上课记录、订单 |

### V1 不包含范围

| 模块 | 暂不包含原因 |
|------|--------------|
| 在线支付 | 涉及支付合规与对账，建议后续独立设计 |
| 完整家长端 | V1 先通过报告和导出满足服务展示 |
| 原生移动 App | V1 使用 Web，后续按使用数据评估 |
| 自动排课算法 | 规则复杂，先保证人工排课稳定 |
| 复杂薪酬结算 | 需要老师结算口径确认 |

## 部署流程

### 环境划分

| 环境 | 用途 | 数据 |
|------|------|------|
| Local | 开发调试 | mock/staging seed |
| Staging | 客户 UAT 和演示 | 客户样本或脱敏数据 |
| Production | 正式使用 | 客户真实数据 |

### 部署步骤

1. 冻结 V1 代码分支。
2. 在 staging 执行完整测试和客户 UAT。
3. 导出 production 目标环境变量清单。
4. 创建 production 数据库和文件存储。
5. 执行 Prisma schema 同步或迁移。
6. 导入客户历史数据。
7. 执行数据核对脚本。
8. 部署后端服务。
9. 部署前端静态资源。
10. 配置域名、HTTPS、CORS 和反向代理。
11. 使用管理员账号完成生产冒烟测试。
12. 开放客户正式账号。

### 生产环境变量

| 变量 | 说明 |
|------|------|
| `DATABASE_URL` | 生产 PostgreSQL 连接 |
| `PORT` | 后端端口 |
| `APP_ENV` | `production` |
| `AUTH_TOKEN_SECRET` | 强随机密钥 |
| `CORS_ORIGIN` | 前端正式域名 |
| `VITE_API_BASE_URL` | 前端访问 API 地址 |
| `VITE_API_PROXY_TARGET` | 代理目标后端地址 |

## 上线后支持

### 支持周期

| 阶段 | 时长 | 支持重点 |
|------|------|----------|
| 上线首日 | 1 天 | 登录、数据核对、紧急问题处理 |
| 上线首周 | 5 个工作日 | 每日问题汇总、缺陷修复、使用指导 |
| 上线首月 | 4 周 | 周度复盘、P1 需求确认和迭代计划 |

### 支持机制

1. 建立客户问题群。
2. 每日收集问题并分级。
3. 阻断问题当日响应。
4. 重要问题 1-2 个工作日内给出修复或 workaround。
5. 每周输出问题清单和处理进度。

## 风险点

| 风险 | 影响 | 应对 |
|------|------|------|
| 历史数据质量差 | 导入失败或余额不一致 | 提前做样本导入和全量试导入 |
| 权限范围理解不一致 | 用户看到不该看的数据 | 上线前逐角色验收 |
| 课时规则复杂 | 消课和余额争议 | 与财务确认规则并保留操作日志 |
| 客户上线前仍在改字段 | 开发返工和导入模板变动 | 设定字段冻结时间 |
| AI 输出不符合客户口吻 | 报告和建议不可直接使用 | V1 保持可编辑，AI 作为辅助 |
| 部署环境网络限制 | 前后端或数据库连接异常 | 提前完成环境连通性测试 |
| 文件存储容量增长 | 附件访问慢或备份困难 | 限制大小并规划对象存储 |

## 回滚方案

### 应用回滚

1. 保留上一个稳定版本的前端构建产物。
2. 后端部署采用版本化发布。
3. 新版本上线前记录镜像/构建版本。
4. 出现阻断问题时切回上一版本。
5. 回滚后保留问题现场日志。

### 数据回滚

| 场景 | 方案 |
|------|------|
| 导入错误 | 按导入批次回滚 |
| 误消课 | 生成反向课时流水，不直接改余额 |
| 误调整课时 | 生成反向调整流水并记录原因 |
| 批量误操作 | 根据操作日志定位影响数据后批量修复 |
| schema 迁移异常 | 使用上线前数据库备份恢复 |

### 回滚触发条件

1. 核心角色无法登录。
2. 学员、排课、消课任一核心流程不可用。
3. 大范围数据权限泄露。
4. 课时余额批量错误且无法快速修复。
5. 数据库迁移导致核心数据不可读。
