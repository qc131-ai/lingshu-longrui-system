# Sprint 5-6 客户试用支持与反馈收敛手册

## 1. 阶段定位

Sprint 5-6 的目标不是继续扩展功能，而是支撑客户 staging 试用，把反馈稳定地收集、分级、复现、修复和回归。

当前系统已经进入“可商业演示和小范围客户试用”阶段。试用期间所有处理原则是：

- 不新增大功能。
- 不重做 UI。
- 不重构主链路。
- 优先修复影响登录、权限、数据隔离、主业务链路、AI Agent 可用性的阻塞问题。
- 需求型反馈先记录和分级，不立即扩大范围。

## 2. 试用支持目标

1. 确保客户能顺利登录 staging。
2. 确保多机构数据隔离稳定。
3. 确保教务主链可演示、可试用、可刷新保留。
4. 确保 DeepSeek AI Agent 可查询、可生成确认卡片、可生成 AI 任务。
5. 将客户反馈沉淀为清晰 backlog。
6. 明确哪些问题必须试用前修复，哪些进入后续 Sprint。

## 3. 反馈分级

| 等级 | 名称 | 判定标准 | 处理目标 |
| --- | --- | --- | --- |
| P0 | 试用阻塞 | 无法登录、白屏、后端 500、核心页面无法打开、跨机构数据泄露、确认消课错误扣减、AI Agent 造成错误写操作 | 当天定位，优先修复并重新部署 |
| P1 | 主链路缺陷 | 排课、上课记录、消课、课时流水、请假补课、家长报告任一关键步骤失败，但有绕行方式 | 1-2 个工作日内修复或给出 workaround |
| P2 | 体验和一致性问题 | 文案不清、错误提示不明确、筛选不好用、字段缺失但不阻塞试用 | 记录到后续小版本 |
| P3 | 新需求 | 新报表、新角色、新审批规则、真实通知、复杂 AI 自动化、支付等 | 放入产品需求池，单独评估 |

## 4. 试用期间响应节奏

建议节奏：

| 时间 | 动作 |
| --- | --- |
| 每天试用前 | 打开后端 health，登录管理员账号，快速检查学员、排课、AI 助手 |
| 客户反馈后 2 小时内 | 完成初步分级，判断是否 P0 / P1 |
| 每天下午 | 汇总当天反馈，更新 issue log |
| 每次修复后 | 运行 `npm run lint`、`npm run backend:typecheck`、`npm run build`，并跑相关 staging smoke test |
| 每周结束 | 输出一份反馈摘要，区分已修复、待修复、后续需求 |

## 5. 标准处理流程

1. 收到反馈。
2. 登记到 `docs/trial-issue-log-template.md` 对应表格。
3. 补齐信息：
   - 机构
   - 账号 / 角色
   - 页面
   - 操作步骤
   - 期望结果
   - 实际结果
   - 截图 / 视频 / 时间点
4. 判断优先级。
5. 本地或 staging 复现。
6. 确认是否需要代码修复。
7. 若修复：
   - 最小改动。
   - 不改 UI 视觉。
   - 不扩大功能范围。
   - 验证相关主链路。
8. 部署后通知客户复测。
9. 将状态改为已解决或转入后续 Sprint。

## 6. 必须优先保障的链路

客户试用期间，以下链路出现问题应优先处理：

1. 登录与角色权限。
2. 多机构隔离。
3. 学员、课程、老师、班级基础数据读取。
4. 排课日历加载、新建、编辑、取消。
5. 从排课生成上课记录。
6. 老师反馈保存与提交。
7. 确认消课、课时余额、课时流水。
8. 请假补课审批和安排。
9. 家长报告生成、编辑、发送状态。
10. AI 教务助手真实数据查询。
11. AI Agent 确认动作和 AI 任务中心。
12. Excel 模板下载、预览、导入、导出。

## 7. 暂时不要做的事情

试用期间除非客户试用被阻塞，否则暂时不要做：

- 接真实微信、短信、邮件发送。
- 接支付。
- 做复杂 BI 报表。
- 让 AI 自动扣课时、自动发送家长报告、自动修改权限。
- 大规模 UI 重设计。
- 大规模数据模型重构。
- 生产环境多租户计费体系。
- 将 staging 测试账号用于生产。

## 8. P0 / P1 修复验收标准

每个 P0 / P1 修复完成后必须满足：

```bash
npm run lint
npm run backend:typecheck
npm run build
```

并按问题类型补充验证：

| 问题类型 | 必须验证 |
| --- | --- |
| 登录问题 | 至少验证管理员和对应角色账号登录 |
| 多机构隔离 | 验证 longrui / wolai / guangwai / amazingx 至少两个机构 |
| 教务主链 | 验证该链路前后一步不会回归 |
| 课时扣减 | 验证余额、流水、防重复消课 |
| AI Agent | 验证 provider、确认卡片、任务中心、越权限制 |
| 导入导出 | 验证模板下载、预览、批次列表、导出 |

## 9. Go / No-Go 判定

可以继续客户试用：

- 无 P0。
- P1 有明确 workaround 或已排期。
- 数据隔离验证通过。
- 登录和核心页面可用。
- AI Agent 不会直接执行高风险写操作。

暂停客户试用：

- 出现跨机构数据泄露。
- 核心账号无法登录。
- 排课 / 上课记录 / 消课任一主链路无法完成。
- AI Agent 绕过确认步骤执行写操作。
- staging 数据库 schema 与代码不一致导致持续 500。

## 10. 当前建议

下一步建议保持为“客户试用支持与反馈收敛”，不要立即进入新功能 Sprint。

推荐输出物：

- 每日试用问题日志。
- 每周反馈摘要。
- P0 / P1 修复记录。
- 后续 Sprint 候选需求池。
